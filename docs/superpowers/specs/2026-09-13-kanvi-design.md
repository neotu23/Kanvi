## 1. 目标

**当前主路径（2026-09-24 起）：** 用固定版本的排版 skill（gzh-beautify）维护一套本地主题库；用户选一套气质，导入自己的 Obsidian Markdown，由服务端调用 DeepSeek 按该主题的槽位把内容装配成可粘贴的公众号正文 HTML；装配结果必须通过 skill 的结构校验与官方检查器，并接受原文保真门禁，通过后才可复制或导出。主题既可以来自上游示例种子，也可以按 brief 由主题工厂生产，但必须逐个确认气质后才入库。

**历史路径（已冻结）：** 用户提供公众号参考链接，系统提取可复用设计，生成样例并完成自动规则检测和修正，再保存可复用模板；随后导入 Markdown 并套用规则检测通过的模板。该路径的代码与测试保留，作为历史证据与备用入口。

模板可表达自定义 HTML 结构与 CSS。Markdown 是内容输入格式，不限制输出只能采用固定标题、段落的预设主题。

## 2. 范围与全局约束

- 本地 Next.js + TypeScript，默认仅监听 127.0.0.1，不公开部署。
- 第一版只生成纯文字公众号正文，不处理音视频、SVG 动效及自动发布；图片按原文地址渲染，不编造图床。
- 默认保留原文和顺序，不润色、不增补事实、不自动生成小标题。
- DeepSeek 仅接收本次任务所需内容，不发送整个 Obsidian 仓库。
- 密钥只在本地服务端读取；不使用 NEXT_PUBLIC_ 前缀，不写入报告和客户端响应。
- 原始参考 HTML、模型输出与上游预览页都视为数据：先清理或校验，再进入受限预览；不执行脚本和事件处理器。
- 上游 skill、主题包与检查器记录实际固定版本；主题包内容发生变化即视为新主题，历史记录不追溯修改。
- 样式内联成功不等于公众号兼容；规则检测与公众号实测分别记录。
- 模板修改产生新版本；实际验证记录不可继承到有变化的新版本。
- 预览、检测、HTML 导出与富文本复制使用同一份最终正文 HTML。
- 自动修正最多两轮；无法修复时保留问题，不默默退回默认风格。
- 用户数据放在 data/，验证产物放在 artifacts/，主题资产放在 themes/ 并提交；密钥、vendor/ 与运行数据不进入 Git。
- 上游源码、依赖和模型配置记录实际版本；新版本不自动改变已验证主题或模板。

本地不等于离线：获取公众号参考、主题生成与文章装配需要联网，DeepSeek API 调用会发送选定内容。主题库读取、规格检查与复制应尽可能不依赖外部服务。

## 3. 模板制作流程（已冻结）

> 2026-09-24 起不再作为主路径。以下内容保留为历史设计与实现说明，相关代码、测试与验证报告不变更。

### 3.1 读取参考

输入公开公众号文章链接。服务端校验 HTTPS、允许的微信文章主机及每次重定向；拒绝私网目标、本地文件和其他协议。设置超时与响应大小上限，并在报告中记录失败原因。

读取正文 DOM、内联样式、必要的样式来源，保存文章区域及样式来源快照。公众号名、阅读量、工具栏等界面不作为模板组成部分。输出为纯文字时忽略媒体素材，明确记录由图片实现的装饰无法直接复用。

验证码、访问限制、正文缺失和网络失败必须返回真实失败。备用入口是用户提供保存的 HTML，不绕过登录或验证。截图输入留待后续，不属于当前实施范围。

### 3.2 提取设计并建立模板

AI 从整理后的 DOM/CSS 声明分析视觉层次，区分有来源的声明和估计，不把静态证据当作浏览器计算布局。当前只实现文字证据分析，不启用截图通道。

保存两部分：

1. 设计描述：配色、字号、行距、留白、对齐、装饰与风格标签。
2. 可执行模板：容器结构、正文/标题/引用等内容位置、可重复区域、可省略区域、CSS 规则。

模板使用声明式结构，不保存任意 JavaScript、React 代码或可执行表达式。普通文本必须转义；强调等行内结构由解析器产生，不能直接拼接用户 HTML。

来源中未出现的元素标为未支持；如需扩展，显式生成对应设计并纳入样例验证。禁止用参考文章的原文或原作者信息填充新日记。

### 3.3 制作样例与运行检查

一篇样例可以覆盖长短段落、长标题、强调，以及模板支持的引用、列表和分隔线。用自动化功能测试检查内容和渲染边界；当前不执行浏览器交互模拟。

顺序：模板渲染 → 清理结构和无关属性 → 样式内联 → 输出正文 HTML → 本地布局与官方规则检测。

检测报告必须记录检查器版本、正文哈希、问题位置、规则编号和错误类型。检查器启动失败、超时或返回内容无法解析时，状态为检测失败，不得当作零问题。

修正前后对照原文和设计。冗余结构可以程序清理；影响视觉的调整通过局部模板补丁实现。每次修正重新生成和检测，最多两轮。检查器自带的 `dedupe` 只用于冗余嵌套，不代表能够自动修复全部问题。

### 3.4 规则检测通过并保存

按用户当前范围，代码实现、自动功能测试和生产构建作为交付验收；公众号实测、系统粘贴和浏览器交互模拟不执行，也不是模板使用门槛。

状态流转：`draft → checking → needs-fix / rule-passed`。读取或检测故障进入 `failed`，可以重试。规则通过记录必须绑定模板版本、样例正文哈希和检查器版本；修改模板创建新 draft，不能继承旧版本通过记录。

`rule-passed` 模板可被手选或匹配使用，但只表示该样例在当前规则下未报告问题。公众号实际兼容性不作保证。如果未来用户主动提供实测结果，另行记录精确版本与样例，不混入规则状态。

## 4. 日常文章流程（已冻结）

> 2026-09-24 起由 4A 节取代。以下为模板套版路径的设计说明。

### 4.1 导入 Obsidian 文档

输入单篇 `.md`；不连接整个仓库。属性区仅取明确映射的标题、日期、标签，不输出为正文。用户显式属性优先，正文标题其次；缺少标题不自动生成。

普通 Markdown 标题、段落、加粗、引用、列表、分隔线转为有稳定 ID 的内容块，记录原文位置。

双链的显示文字可保留为普通文字，但不伪造跳转地址。Obsidian 提示块需要明确映射为模板引用/提示区域；不支持的媒体嵌入、块引用、脚注或语法列出诊断，阻止静默丢失。原始 HTML 默认不执行，提示用户处理。

### 4.2 选择模板并渲染

先根据内容结构筛选规则检测通过且适配的模板，再由 DeepSeek 根据标签、篇幅和气质排序。结构匹配是硬条件，视觉偏好是软条件。无适用模板时提示选择调整方式，不默认使用未通过规则检测的模板。

AI 返回模板 ID、版本和推荐原因，不重写全文。若需要强调安排，只引用内容块 ID 与合法文本区间；校验边界后由本地程序读取原文。

用户可以手动选择模板。API 不可用时，仍可以手动使用适配且规则检测通过的模板。

### 4.3 本篇检查与输出

检查内容块次序、段落遗漏、重复、非预期新增，以及官方工具覆盖的问题。新标题长度和段落组合仍可能产生布局问题，规则检测通过的模板不能跳过本篇检查。

安全修正不改动原文。必须扩展模板结构时创建新版本，并重新完成该版本的样例规则检测。

最终输出：可视预览、可复制正文、独立 HTML 文件和本地历史记录。复制按钮在用户点击时写入 `text/html` 及 `text/plain`，不能复制 HTML 代码文本冒充富文本。剪贴板失败时展示明确失败和手动选择预览内容的备用方式。

## 4A. 风格主题主流程（当前）

2026-09-26 导航整理：`/` 首页仅保留选主题、完整样例预览和进入正文生成；`/styles` 为兼容入口。`/studio` 集中主题制作与草案；`/history` 读取正文历史及报告；`/settings` 集中运行状态、备份恢复、存储路径及旧工具入口。原首页排版样例移至 `/demo`。

### 4A.1 主题库与来源

本地主题库位于 `themes/<id>/`，每个主题包含 `theme.json`、`THEME.md`、`preview.html`（上游契约要求三件套缺一不可），以及本项目补充的来源记录 `SOURCE.json` 与人类可读的 `SOURCE.md`。来源有两类：

1. **种子（seed）**：固定 commit 的上游示例主题，由 `npm run theme:seed` 从 `vendor/gzh-beautify-skill/examples/themes/` 复制，内容不修改，来源记录绑定上游 URL、commit 与许可。
2. **生成（generated）**：主题工厂按 brief 产出，记录模型、提示词版本、skill commit 与 brief 指纹。

主题可删除（需二次确认）：删除只影响主题包本身，不删除渲染历史；种子可由 `npm run theme:seed` 从固定版本重新复制，自有主题删除后不可恢复。删除与入库都不自动提交 Git。

### 4A.2 主题工厂（草案 → 逐个确认）

1. 用户提供 brief（气质、场景、偏好）。服务端把上游 skill 规范（`theme-factory.md`、`theme-schema.md`、`theme.schema.json`、`wechat-constraints.md`、`design-system.md`）作为系统提示词，brief 只作为数据。
2. 分两次模型调用：先产出 `theme.json` 与 `THEME.md`，再据其产出 `preview.html`。响应字段严格白名单校验，`theme.json` 必须通过项目内的主题契约校验。
3. 草案写入 `data/theme-drafts/<主题id>/` 并立即运行 `lint_theme.py`；**不直接写入 `themes/`**。
4. 用户在 `/studio` 预览草案气质后确认或丢弃。确认时重新运行 lint（草案可能被手改）、校验主题 id 不与库里冲突，写入来源记录后原子移动到 `themes/<主题id>/`。

模板制作采用三栏：搜索和选择主题/草案、编辑名称及设计提示词/本次调整、完整样例与前后对比。没有原始提示词的主题使用明确标注的整理说明。生成时服务端加载父主题结构，要求仅调整指定部分，使用独立主题 ID；实际设计提示词、调整要求、父主题快照和程序识别的变化写入可选 `DESIGN.json`，并随备份恢复。保存不覆盖原主题。草案必须可呈现完整样例，未知变量或正文缺失直接报错。入库移动成功后才清理草案记录，失败可重试。

### 4A.3 文章装配与双校验

2026-09-25 界面补充：先展示同一篇已保存的自写完整文章，使用主题 `THEME.md` 的正文槽位装配；预览高度随全文及窗口宽度变化，不设置内部滚动区。已保存主题不显示确认按钮，用户点击顶部“进入生成正文”打开 Markdown 输入区。新生成的草案自动打开预览，右上角显示“未保存主题”，点击保存入库后方可生成正文；预览底部不设按钮。切换主题保留输入内容。示例原文在 `public/samples/slow-afternoon.md`，可从界面下载。预览不调用模型，不继承或伪造正文检测结果；槽位不支持或丢失正文时明确失败。上游 `preview.html` 不修改，继续作为主题包契约资产保留。

1. 输入单篇 Markdown（256 KiB / 20 万字符上限）。解析为带类型的内容单元，覆盖标题、章节、段落、引用、列表、表格、代码块、图片与分隔线。
2. 选定主题后组装提示词：该主题的 `THEME.md` 与 `theme.json`、skill 的 `render-contract.md` 与 `wechat-constraints.md`；文章正文上限 60 KiB，超过直接报错，不截断后声称已发送完整内容。
3. 模型只输出 `{html, notes}`。含 `<script>`、事件属性、可执行 URL、`<style>`/`<iframe>` 等嵌入标签、完整文档外壳的输出一律拒绝保存。
4. 两道检查都通过才算“规格检查通过”：skill 的 `validate_article.py --strict`（要求 0 ERROR / 0 WARN）与官方 `wechat-spec` 检查器（真实 Chrome）。检查器故障、超时或报告与正文/检查器版本不匹配时状态为失败，不显示通过。
5. 原文保真门禁：把每个内容单元切成句子级片段，要求按顺序在产物可见文字中命中；缺段、改写、换序或残留 Markdown 标记都判为“需要修正”。2026-10-13 起，新正文目录只能沿用原文，主题提供 toc 槽不代表必须使用；最终提示词覆盖上游的三看点要求，新增、重复或扩写可识别目录判为需修正。新规则也计入单字条目和仅在属性区提供的标题。章节编号、英文标签等装饰性新增单独列出供人工核对。旧历史按其提示词版本复算，不追溯修改原结论。
6. 结果落盘为不可变记录 `data/renders/<记录ID>/record.json` 与独立报告 `result/report.json`，其中保存主题内容快照（`theme.json` + `THEME.md` 与哈希），因此主题被删除后历史仍可读取与复算。

`rule-passed` 状态绑定该产物哈希、主题快照哈希、skill commit、提示词版本与检查器版本，只表示这份产物在当前固定版本下未报告问题，不等于公众号实测通过。

## 5. 技术边界

| 模块 | 职责 | 不承担 |
|---|---|---|
| 参考读取器（已冻结） | 取得文章及样式证据 | 绕过访问限制 |
| DeepSeek 适配器 | 结构化设计、主题生产、正文装配、局部修正建议 | 直接操作本地程序或公众号 |
| 主题库 | 读取与校验主题包、来源记录、删除与恢复 | 修改上游主题内容 |
| 上游 skill 适配器 | 以固定版本子进程运行 lint/validate/preview 脚本并解释结果 | 复制或改写上游规则 |
| 模板渲染器（已冻结） | 内容位置映射、结构重复、原文保真 | 任意脚本执行 |
| WeMD/Juice 适配器 | HTML/CSS 处理与内联 | 证明所有微信环境兼容 |
| 微信规则检查适配器 | 隔离运行本地 CLI、解释结果 | 完整 CSS 支持矩阵、内容审核 |
| 本地仓库 | 文件持久化、版本和历史 | 云同步 |
| 页面 | 输入、状态、预览、复制 | 完整富文本编辑器 |

WeMD 是候选实现来源，不将其整个编辑器作为必需依赖。先验证独立函数及依赖能否在本地 Next.js 服务端正确运行；若抽取成本高，可直接使用 Juice，并保留所需的公众号处理规则及来源记录。该替换不能减少官方规则检查与内容完整性检查。

检测器与 skill 脚本都作为本地子进程运行，固定可执行程序（Node 或 `python3`），参数数组传入已写入的本地文件；不拼接 shell，限制时间与输出大小。浏览器实例按任务限制时间和资源。预览通过受限 iframe 隔离，不运行外部脚本，不在文档中包含 API Key。

## 6. 数据契约

以下为设计目标契约；实现以 `src/features` 中代码为准。模板链路的定义、版本与内容块已落在 `templates/schema.ts`、`repository.ts`、`render.ts`；Markdown 源位置与诊断在 `articles/parse-markdown.ts`。主题链路见 `themes/schema.ts`（主题与来源契约）、`themes/library.ts`、`themes/repository.ts`（渲染记录与主题快照）。

```ts
type TemplateStatus =
  | 'draft' | 'checking' | 'needs-fix'
  | 'rule-passed' | 'failed';

type ContentKind = 'heading' | 'paragraph' | 'quote' | 'list' | 'divider';

interface ArticleBlock {
  id: string;
  kind: ContentKind;
  sourceStart: number;
  sourceEnd: number;
  sourceText: string;
  level?: number;
}

interface CheckIssue {
  rule: string;
  message: string;
  selector?: string;
}

interface CheckReport {
  status: 'passed' | 'violations' | 'error';
  htmlHash: string;
  checkerCommit: string;
  issues: CheckIssue[];
  error?: string;
}

interface RenderedArticle {
  id: string;
  templateId: string;
  templateVersion: string; // UUID
  bodyHtml: string;
  plainText: string;
  htmlHash: string;
  check: CheckReport;
}

type ThemeOrigin = 'seed' | 'generated' | 'local';

interface ThemeSource {
  version: 1;
  origin: 'seed' | 'generated';
  createdAt: string;
  upstream?: { id: string; url: string; commit: string; path: string; license: string };
  generated?: { model: string; promptVersion: string; skillCommit: string; briefHash: string };
}

interface RenderRecord {
  schemaVersion: 1;
  id: string;
  createdAt: string;
  markdown: string;
  parsed: unknown;                 // 内容单元、统计、诊断
  theme: { id: string; name: string; definitionHash: string; themeJson: unknown; themeMarkdown: string; origin: ThemeOrigin };
  skill: { commit: string; promptVersion: string };
  model: string;
  articleHash: string;
  themeHash: string;
  rawOutputHash: string;
  artifact: { bodyHtml: string; plainText: string; htmlHash: string };
  validate: { ok: boolean; errorCount: number; warnCount: number; issues: unknown[]; raw: string };
  fidelity: { ok: boolean; missing: string[]; added: string[]; residue: string[] };
}
```

模板记录还包括源链接、来源快照索引、设计描述、结构支持列表、HTML/CSS 规则、标签、状态、版本、样例索引和验证记录。主题记录包含来源类型、“气质”标签（craft/mood/scenes）、结构模型、九色与字体令牌，以及定义哈希。渲染记录中的主题快照是“删除主题后历史仍可读”的前提。

## 7. 本地文件与版本控制

```text
themes/<id>/           # 主题包（提交）：theme.json、THEME.md、preview.html、SOURCE.json、SOURCE.md
data/
  theme-drafts/<id>/   # 待确认的主题草案（不提交）
  renders/<id>/        # 渲染记录、报告与主题快照（不提交）
  references/<id>/     # 来源 HTML、静态样式证据、元信息（冻结链路）
  analyses/<referenceId>/<id>/ # 独立的设计分析草稿（冻结链路）
  templates/<id>/<version>/    # 模板版本（冻结链路）
  articles/<id>/       # Markdown、生成正文、历史（冻结链路）
  validation/<id>/     # 报告与实际验证记录

```

首次使用明确显示存储路径。写入采用临时文件后原子替换；主题入库与模板版本都不可原地覆盖；重启后可恢复。第一版不引入数据库、账户、多用户权限或云同步。

Git 只管理源码、文档、锁文件、上游版本清单、自写测试样例与主题资产。上游许可证和采用来源必须随复用代码保留，不因来源目录被忽略而遗漏授权声明。

## 8. 验收标准

当前主路径：

1. 用自写 Markdown 与已入库主题能产出可粘贴正文，skill 校验与官方检查器都通过后才启用复制或下载。
2. 主题库包含固定版本种子主题与经逐个确认的自有主题；主题可删除且删除后渲染历史仍可读，种子可由脚本恢复。
3. 原文按句子片段逐块保真；脚本、事件属性、可执行 URL、嵌入标签与改写原文都被拒绝并给出证据。
4. 任一校验失败、检查器故障或记录绑定不一致时不显示通过；本地重启后主题、草案与历史仍可读取。
5. 未配置模型时仍可浏览主题库、草案与历史，不显示伪造的生成结果。

冻结路径（保持原状）：

6. 一个参考链接产生可追溯设计与自定义模板，失败时不给出伪造成功。
7. 只有绑定精确版本和样例的规则检测成功，模板才标为规则检测通过并可复用；不要求公众号实测。
8. AI 不可用时可手动选择模板，检测器不可用时不能显示检测通过。
9. 第一版全过程不依赖完整编辑器，不自动发布到公众号。
