# Kanvi 产品与技术设计

日期：2026-09-13
状态：产品设计基线。2026-09-15 已实现基础链路、参考导入、设计分析及模板工作台及 Markdown 手选套版、本篇检测与历史；AI 推荐待实施。模板语义映射和检查器限制见第 9 节。
当前授权：初始化、推送私有 GitHub 仓库并执行阶段计划。

## 1. 目标

用户提供公众号参考链接，系统提取可复用设计，生成样例并完成自动规则检测和修正，再保存可复用模板。日常导入 Obsidian Markdown，匹配规则检测通过的模板，输出可预览、导出和复制的公众号正文。

模板可表达自定义 HTML 结构与 CSS。Markdown 是内容输入格式，不限制输出只能采用固定标题、段落的预设主题。

## 2. 范围与全局约束

- 本地 Next.js + TypeScript，默认仅监听 127.0.0.1，不公开部署。
- 第一版只生成纯文字公众号正文，不处理图片、音视频、SVG 动效及自动发布。
- 默认保留原文和顺序，不润色、不增补事实、不自动生成小标题。
- DeepSeek 仅接收本次任务所需内容，不发送整个 Obsidian 仓库。
- 密钥只在本地服务端读取；不使用 NEXT_PUBLIC_ 前缀，不写入报告和客户端响应。
- 原始参考 HTML 与模型输出先清理，再进入受限预览；不执行脚本和事件处理器。
- 样式内联成功不等于公众号兼容；规则检测与公众号实测分别记录。
- 模板修改产生新版本；实际验证记录不可继承到有变化的新版本。
- 预览、检测、HTML 导出与富文本复制使用同一份最终正文 HTML。
- 自动修正最多两轮；无法修复时保留问题，不默默退回默认风格。
- 用户数据放在 data/，验证产物放在 artifacts/，均不进入 Git。
- 上游源码、依赖和模型配置记录实际版本；新版本不自动改变已验证模板。

本地不等于离线：获取公众号参考需要联网，DeepSeek API 调用会发送选定内容。模板应用、规则检查和复制应尽可能不依赖外部服务。

## 3. 模板制作流程

### 3.1 读取参考

输入公开公众号文章链接。服务端校验 HTTPS、允许的微信文章主机及每次重定向；拒绝私网目标、本地文件和其他协议。设置超时与响应大小上限，并在报告中记录失败原因。

读取正文 DOM、内联样式、必要的样式来源，保存文章区域及样式来源快照。公众号名、阅读量、工具栏等界面不作为模板组成部分。输出为纯文字时忽略媒体素材，明确记录由图片实现的装饰无法直接复用。

验证码、访问限制、正文缺失和网络失败必须返回真实失败。备用入口是用户提供保存的 HTML，不绕过登录或验证。截图输入留待后续，不属于当前实施范围。

### 3.2 提取设计并建立模板

AI 从整理后的 DOM/CSS 声明分析视觉层次，区分有来源的声明和估计，不把静态证据当作浏览器计算布局。当前只实现文字证据分析，不启用截图通道。

保存两部分：

1. 设计描述：配色、字号、行距、留白、对齐、装饰与风格标签。
2. 可执行模板：容器结构、正文/标题/引用等内容位置、可重复区域、可省略区域、CSS 规则。

模板使用声明式结构，不保存任意 JavaScript、React 代码或可执行表达式。普通文本必须转义；强调等行内结构由解析器产生，不能直接拼接用户 HTML。

来源中未出现的元素标为未支持；如需扩展，显式生成对应设计并纳入样例验证。禁止用参考文章的原文或原作者信息填充新日记。

### 3.3 制作样例与运行检查

一篇样例可以覆盖长短段落、长标题、强调，以及模板支持的引用、列表和分隔线。用自动化功能测试检查内容和渲染边界；当前不执行浏览器交互模拟。

顺序：模板渲染 → 清理结构和无关属性 → 样式内联 → 输出正文 HTML → 本地布局与官方规则检测。

检测报告必须记录检查器版本、正文哈希、问题位置、规则编号和错误类型。检查器启动失败、超时或返回内容无法解析时，状态为检测失败，不得当作零问题。

修正前后对照原文和设计。冗余结构可以程序清理；影响视觉的调整通过局部模板补丁实现。每次修正重新生成和检测，最多两轮。检查器自带的 `dedupe` 只用于冗余嵌套，不代表能够自动修复全部问题。

### 3.4 规则检测通过并保存

按用户当前范围，代码实现、自动功能测试和生产构建作为交付验收；公众号实测、系统粘贴和浏览器交互模拟不执行，也不是模板使用门槛。

状态流转：`draft → checking → needs-fix / rule-passed`。读取或检测故障进入 `failed`，可以重试。规则通过记录必须绑定模板版本、样例正文哈希和检查器版本；修改模板创建新 draft，不能继承旧版本通过记录。

`rule-passed` 模板可被手选或匹配使用，但只表示该样例在当前规则下未报告问题。公众号实际兼容性不作保证。如果未来用户主动提供实测结果，另行记录精确版本与样例，不混入规则状态。

## 4. 日常文章流程

### 4.1 导入 Obsidian 文档

输入单篇 `.md`；不连接整个仓库。属性区仅取明确映射的标题、日期、标签，不输出为正文。用户显式属性优先，正文标题其次；缺少标题不自动生成。

普通 Markdown 标题、段落、加粗、引用、列表、分隔线转为有稳定 ID 的内容块，记录原文位置。

双链的显示文字可保留为普通文字，但不伪造跳转地址。Obsidian 提示块需要明确映射为模板引用/提示区域；不支持的媒体嵌入、块引用、脚注或语法列出诊断，阻止静默丢失。原始 HTML 默认不执行，提示用户处理。

### 4.2 选择模板并渲染

先根据内容结构筛选规则检测通过且适配的模板，再由 DeepSeek 根据标签、篇幅和气质排序。结构匹配是硬条件，视觉偏好是软条件。无适用模板时提示选择调整方式，不默认使用未通过规则检测的模板。

AI 返回模板 ID、版本和推荐原因，不重写全文。若需要强调安排，只引用内容块 ID 与合法文本区间；校验边界后由本地程序读取原文。

用户可以手动选择模板。API 不可用时，仍可以手动使用适配且规则检测通过的模板。

### 4.3 本篇检查与输出

检查内容块次序、段落遗漏、重复、非预期新增，以及官方工具覆盖的问题。新标题长度和段落组合仍可能产生布局问题，规则检测通过的模板不能跳过本篇检查。

安全修正不改动原文。必须扩展模板结构时创建新版本，并重新完成该版本的样例规则检测。

最终输出：可视预览、可复制正文、独立 HTML 文件和本地历史记录。复制按钮在用户点击时写入 `text/html` 及 `text/plain`，不能复制 HTML 代码文本冒充富文本。剪贴板失败时展示明确失败和手动选择预览内容的备用方式。

## 5. 技术边界

| 模块 | 职责 | 不承担 |
|---|---|---|
| 参考读取器 | 取得文章及样式证据 | 绕过访问限制 |
| DeepSeek 适配器 | 结构化设计、推荐、局部修正建议 | 直接操作本地程序或公众号 |
| 模板渲染器 | 内容位置映射、结构重复、原文保真 | 任意脚本执行 |
| WeMD/Juice 适配器 | HTML/CSS 处理与内联 | 证明所有微信环境兼容 |
| 微信规则检查适配器 | 隔离运行本地 CLI、解释结果 | 完整 CSS 支持矩阵、内容审核 |
| 本地仓库 | 文件持久化、版本和历史 | 云同步 |
| 页面 | 输入、状态、预览、复制 | 完整富文本编辑器 |

WeMD 是候选实现来源，不将其整个编辑器作为必需依赖。先验证独立函数及依赖能否在本地 Next.js 服务端正确运行；若抽取成本高，可直接使用 Juice，并保留所需的公众号处理规则及来源记录。该替换不能减少官方规则检查与内容完整性检查。

检测器作为本地子进程运行，固定可执行程序，参数数组传入已写入的本地文件；不拼接 shell。浏览器实例按任务限制时间和资源。预览通过受限 iframe 隔离，不运行外部脚本，不在文档中包含 API Key。

## 6. 数据契约

以下为后续文章流程的目标契约；实现以 src/features 中代码为准。现有模板定义、版本及内容块已分别落在 templates/schema.ts、repository.ts、render.ts：版本为 UUID，正文类型名为 body；Markdown 的源位置、原文和诊断现已在 articles/parse-markdown.ts 实现并与内容块分开保存。上游不提供 selector，当前保留 paragraphIndex 与 outerHTML。

```ts
type TemplateStatus =
  | 'draft' | 'checking' | 'needs-fix'
  | 'rule-passed' | 'failed';

type ContentKind = 'heading' | 'paragraph' | 'quote' | 'list' | 'divider';

interface ArticleBlock {
  id: string;
  kind: ContentKind;
  sourceStart: number;
  sourceEnd: number;
  sourceText: string;
  level?: number;
}

interface CheckIssue {
  rule: string;
  message: string;
  selector?: string;
}

interface CheckReport {
  status: 'passed' | 'violations' | 'error';
  htmlHash: string;
  checkerCommit: string;
  issues: CheckIssue[];
  error?: string;
}

interface RenderedArticle {
  id: string;
  templateId: string;
  templateVersion: string; // UUID
  bodyHtml: string;
  plainText: string;
  htmlHash: string;
  check: CheckReport;
}
```

模板记录还包括源链接、来源快照索引、设计描述、结构支持列表、HTML/CSS 规则、标签、状态、版本、样例索引和验证记录。模板语法已按“无脚本、可重复、可省略、明确内容位置”实现；来源证据、合成节点和区域映射随定义保存。样例与检测记录放在版本目录内，不可变报告绑定版本、模板定义哈希和正文哈希。

## 7. 本地文件与版本控制

```text
data/
  references/<id>/      # 来源 HTML、静态样式证据、元信息
  analyses/<referenceId>/<id>/ # 独立的设计分析草稿
  templates/<id>/<version>/
  articles/<id>/        # Markdown、生成正文、历史
  validation/<id>/      # 报告与实际验证记录
artifacts/             # 检测与开发输出
vendor/                # 固定提交的上游工作副本
```

首次使用明确显示存储路径。写入采用临时文件后原子替换；模板版本不可原地覆盖；重启后可恢复。第一版不引入数据库、账户、多用户权限或云同步。

Git 只管理源码、文档、锁文件、上游版本清单及自写测试样例。上游许可证和采用来源必须随复用代码保留，不因来源目录被忽略而遗漏授权声明。

## 8. 验收标准

1. 一个参考链接产生可追溯设计与自定义模板，失败时不给出伪造成功。
2. 只有绑定精确版本和样例的规则检测成功，模板才标为规则检测通过并可复用；不要求公众号实测。
3. 两篇不同结构、不同长度的日记可套用同一模板，默认原文和次序不变。
4. AI 不可用时可手动选择模板，检测器不可用时不能显示检测通过。
5. 输出预览、导出和复制的正文 HTML 一致；无漏段、重复、溢出或已知规则违规。
6. 本地重启后模板和历史仍可读取，Git 中不含真实日记或密钥。
7. 第一版全过程不依赖完整编辑器，不自动发布到公众号。
