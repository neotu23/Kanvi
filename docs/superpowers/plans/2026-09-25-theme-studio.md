# 模板制作与导航整理实施计划

依据：用户在本对话批准的三栏模板制作页方案。主代理实现，子代理仅探索和核验。

## 已批准范围

首页仅选择主题、完整示例预览、进入正文生成。导航为首页、模板制作、文章历史、设置。旧工具保留，在设置内提供入口，原排版样例改至 `/demo`。

模板制作 `/studio`：左侧搜索已保存主题与草案，中间编辑名称、设计提示词和本次调整要求，右侧切换当前/调整后完整文章。可新建、基于当前模板微调、继续调整草案。没有原始提示词的旧模板明确显示整理说明。新草案显示“未保存主题”，保存时保留原版，返回首页可选新模板。

## 实施顺序

1. 增加可选 `DESIGN.json`：保存实际设计提示词、调整要求、父模板快照、程序计算的变化列表。旧主题缺失此文件时按主题参数整理说明。损坏文件报错；备份恢复覆盖此文件。
2. 新增设计读取与草案生成 API；服务端加载父模板，不接受客户端 HTML。生成使用独立 ID，传入父模板完整结构，明确要求只改指定部分。验证草案能完整呈现示例文章，不执行输入脚本。
3. 抽取共享请求、加载状态与文章结果组件。首页移除工厂、草案、备份、路径、历史及运行环境诊断。
4. 新增模板制作、文章历史、设置页面；历史可点击读取已保存产物并复制/下载。生成受模型配置约束，未配置可浏览和编辑。
5. 自动测试覆盖提示词来源、父模板保留、草案保存/重读/备份恢复、输入边界、真实样例预览、历史读取与页面职责；执行全量测试、类型检查、构建和独立核查。

## 边界

不做拖拽编辑器，不自动发布，不更改冻结的参考/模板转换逻辑。新增主题与旧主题并存，原版始终可选；不做覆盖更新。模型的局部调整质量不能用受控测试代替真实调用，界面展示程序识别的变化供确认。仅执行自动化功能测试，不执行浏览器交互模拟或公众号实测。
