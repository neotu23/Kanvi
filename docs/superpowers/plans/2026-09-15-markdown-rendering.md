# 第四阶段：Markdown 原文保真套版

日期：2026-09-15。状态：代码及自动验证已完成。前置阅读：[设计基线](../specs/2026-09-13-kanvi-design.md)、[第三阶段报告](../../validation/2026-09-15-template-rendering.md)。主代理实施，子代理仅探索与核验。

## 目标和边界

单篇 Obsidian Markdown → 带源位置的内容块和诊断 → 手选结构适配且样例规则通过的模板版本 → 本篇渲染与独立检查 → 本地历史、预览、下载和复制。

本阶段不增加 AI 推荐、润色、事实补写、整个 Obsidian 仓库同步或完整编辑器。只做代码、自动测试、生产构建和服务端接口验证；不执行公众号实测、系统粘贴或浏览器交互模拟。

沿用 `ContentBlock`、`renderTemplate`、`TemplateRepository.detail`、`OutputArtifact` 和固定检查适配器。现有正文类型为 `body`，模板版本为 UUID；文章源位置元数据单独存放，不向现有严格内容块接口塞入未知字段。模板样例报告不得冒充本篇报告。

## Task 1：解析契约与来源追踪

- [x] 先审查可复用的 Markdown 解析依赖，选择保留源位置的 AST 解析器；确定版本、许可并提交锁文件，不用正则拼成完整解析器。
- [x] 定义文档输入、元数据、内容块、源范围及诊断契约。每个块有稳定 ID、源偏移和原文；正文字符及顺序可以追溯，Markdown 标记与可见文字的转换有明确记录。
- [x] 覆盖标题、段落、换行、加粗/斜体、引用、无序和有序列表、分隔线；不能表达的嵌套组合报错，不压平后宣称完整保真。
- [x] 用自写样例测试重复段落、实体字符、转义、中文标点、空文件及长度边界；不执行原始 HTML。

## Task 2：Obsidian 转换边界

- [x] 属性区独立解析，标题/日期/标签作为元信息，不擅自增加正文标题；无效属性区定位并报错。明确允许的字段、大小和复杂度。
- [x] 双链保留显示文字并报告转换，不伪造链接；提示块转换为支持的引用结构时保留标题和正文，明确标注转换规则。
- [x] 媒体嵌入、块引用、脚注、代码、表格、普通链接等凡现有内容契约不能无损表达者提供源位置诊断。新增支持需同时扩展渲染、保真检查和测试；否则阻止成功输出，不静默删除。

## Task 3：模板资格与文章渲染

- [x] 本地读取精确模板版本及有效规则通过记录，按正文实际元素筛选；无适配模板时显示原因，不自动降级为未通过模板。
- [x] 不依赖 AI，手动选择模板即可渲染；对正文类型、强调、标题级别、列表等逐项校验支持情况。
- [x] 本地从解析内容填充模板，核验字符、块和组内顺序，无新增、遗漏、重复或改写。
- [x] 对每篇最终正文调用官方检查器；检查故障、哈希不匹配或违规不能显示通过。已知行内片段误报保留，不删强调、不扩大行距来掩盖。
- [x] 本阶段不自动修改模板。需要样式修正时回模板工作台生成新版本、重新检测样例，再重新生成文章。

## Task 4：历史、接口和页面

- [x] 文章记录绑定原始 Markdown 哈希、解析版本、模板版本/定义哈希、最终正文哈希和本篇报告；用不可变记录及原子发布保存到 `data/articles/`。
- [x] 限制上传大小、UTF-8、请求来源、并发和超时；拒绝任意路径及外部提供的 HTML/通过报告。取消和中断不能留下假通过记录。
- [x] 生成页提供单篇文件导入、元信息/诊断、手选模板、检查状态、预览、下载、复制及历史。失败保留可读原因，不加入编辑器。
- [x] 预览、下载、复制共用本篇检查绑定的同一份正文；只有本篇规则通过才启用正常复制入口，未通过下载需明确标注。

## Task 5：验证与交付

- [x] 两篇结构和长度不同的自写日记验证完整性；包含适配成功、模板缺少元素、解析不支持结构与检查器失败路径。
- [x] 自动测试覆盖有序列表、不同标题级别及斜体等第三阶段样例未穷举的内容；原文保真不等同于这些组合已通过微信检查。
- [x] 用真实检查器完成至少一篇合法纯文字文章的检查；保留强调误报案例的真实失败状态，其他边界可用受控报告验证。
- [x] 完成类型检查、相关自动测试、生产构建、生产 HTTP 核验和新仓储实例读取历史。
- [x] 更新 README、路线、事实报告与第五阶段计划，提交并推送已授权私有 GitHub；用户文档、密钥与产物不进入 Git。

## 完成标准

已有规则通过且结构适配的模板可在不调用 AI 的情况下生成用户单篇 Markdown 正文；原文及结构变化可追踪，不支持内容有明确阻断诊断。本篇规则结果独立绑定并保存，重启后能读取同一份输出。真实公众号接受程度不属于此阶段结论。

## 实际完成与边界

- Markdown 采用锁定版本的 mdast / micromark CommonMark、GFM、frontmatter AST，属性区使用 yaml 2.9.1。原文位置以 UTF-16 偏移和行列记录，修正前导 BOM 的位置偏差。
- `parse-markdown.ts` 同时处理有限的 Obsidian 转换，`eligibility.ts` 处理模板资格，`workflow.ts` 负责本篇检测，`repository.ts` 保存不可变文章和报告。未按计划占位文件名机械拆分模块。
- 标题级别与有序列表起始编号随正文保留；属性标题不补写到正文。折叠提示块、复杂引用/列表、媒体、脚注、代码、表格、链接、删除线和原始 HTML 明确阻止生成。
- 提示块含强调标题、双链部分未闭合、诊断数量上限、BOM/CRLF 源位置均补齐回归测试。34 项新增测试加既有 77 项，共 111 项通过。
- 两篇自写日记完成实际官方检查；含强调探针保留 line-height 违规，未伪造模板启用资格。13 项生产 HTTP 核验、类型检查和构建通过。
- 历史保存原始 Markdown、解析结果、模板快照及本篇正文/报告，重建解析与渲染后核对，损坏记录报错。重试创建新文章，不覆盖旧历史；列表每页 20 项按 ID 游标排列，尚未提供备份/恢复。
- 事实证据见 [第四阶段报告](../../validation/2026-09-15-markdown-rendering.md)。后续执行 [第五阶段 AI 推荐](2026-09-15-template-recommendation.md)，不自动启用未检测模板。
