# 第三阶段：模板生成与样例规则检测

日期：2026-09-15。状态：待实施，本文不表示模板功能已存在。

前置阅读：[设计基线](../specs/2026-09-13-kanvi-design.md)、[第二阶段报告](../../validation/2026-09-15-reference-analysis.md)。主代理实施，子代理仅探索和核查。

## 目标与已具备能力

已保存的设计草稿 → 声明式模板版本 → 自写样例 → 输出与规则检测 → 可复用模板。

现有接口包括 `ReferenceSnapshot`、`AnalysisRecord`、`DesignAnalysis`、`buildOutput`、`runChecker` 和 `CheckReport`。阶段 2 的分析记录始终为 draft；它没有检测状态，不得直接当成可用模板。

本阶段只做代码、自动功能测试、生产构建和官方检查器集成。公众号实测、系统粘贴、浏览器交互模拟不执行，不作为模板启用门槛。界面使用“规则检测通过”，不声称微信保证兼容。

## Task 1：模板语法与样式映射

- [ ] 先写语法与渲染边界测试：未知标签/属性、脚本表达式、超深结构、循环引用、空内容位置、原作者文字残留。
- [ ] 定义受限声明式节点：标签、样式、子节点、内容位置。允许标题/正文/引用/列表/强调/分隔等元素自定义嵌套、边框和留白，不固化为一套 Markdown 主题。
- [ ] 标签、属性与数值边界必须匹配 `buildOutput` 的实际支持范围；模型不得返回 JSX、JavaScript 或动态表达式。
- [ ] 将 `DesignProperties` 转为确定的 CSS 声明；继承、字体替代和来源未覆盖的区域显式标注。若只凭现有 schema 不足以表达设计，报告待扩展，不静默替换默认主题。
- [ ] 模板保留来源参考 ID、分析 ID、标签、支持的内容类型和证据映射，不带入参考文章原文。
- [ ] 测试通过后提交模板契约与映射模块。

## Task 2：内容位置与原文保真渲染

- [ ] 先用自写内容块测试：长标题、长短段落、中文标点、加粗、引用、多项列表、空可选区域及重复段落。
- [ ] 同一类内容可重复渲染，允许指定区域省略；原文必须转义，行内强调由受限内容结构产生。
- [ ] 检查原文和顺序：不新增、遗漏、重复或改写内容。模板不支持的结构阻止成功输出并列出诊断。
- [ ] 渲染结果进入现有 `buildOutput`；预览、检测、下载、复制使用同一 `OutputArtifact`，不分别重新生成。
- [ ] Markdown 解析仍留在阶段 4，本阶段使用明确的内容块夹具。

## Task 3：不可变版本与规则状态

- [ ] 模板与版本分别有程序生成的 ID；校验数据后再原子发布，已有版本不可覆盖。
- [ ] 状态流转为 `draft → checking → needs-fix / rule-passed`；检查器故障为 `failed`。
- [ ] 规则记录绑定模板版本、样例正文哈希和检查器提交；模板变化创建新 draft，不继承通过结果。
- [ ] `rule-passed` 才进入可复用候选；模型分析成功、内联成功均不能绕过规则检测。
- [ ] 测试并发重复写入、损坏/缺失记录、重启恢复、失败重试以及版本与报告不匹配。

## Task 4：样例检测与受限修正

- [ ] 为每套模板生成覆盖其支持元素的自写样例；记录未覆盖范围。
- [ ] 调用固定版本官方检查器，保留已有错误规范化、超时和子进程清理。
- [ ] 针对可定位的明确问题生成局部补丁，补丁只能引用现有模板节点及允许样式属性。无法定位时保留问题，不让 AI 全文重写。
- [ ] 修正最多两轮，每轮重新渲染、校验内容完整性和运行规则检测，保存前后差异。
- [ ] 仍有问题时停在 needs-fix；不能清空样式、抹去诊断或换成默认主题来通过检测。
- [ ] 使用真实检查器运行正常/故障样例；模型调用使用可控响应测试，无服务端 Key 不伪造真实调用。

## Task 5：模板工作台与交付

- [ ] 从参考设计草稿进入模板制作，显示来源证据、版本、支持元素及待确认估计。
- [ ] 提供样例生成、规则检测/修正、最终预览、复制与 HTML 下载，复用现有输出组件。
- [ ] 列表区分草稿、需修正、检测失败和规则检测通过；不加入完整富文本编辑器。
- [ ] 完成行为测试、类型检查、生产构建和服务端接口集成；不执行浏览器交互模拟。
- [ ] 更新事实报告和阶段 4 Markdown 计划，提交代码并推送已授权的私有 GitHub 仓库。

## 完成标准

至少一套来自受控设计分析的自定义模板完成样例渲染与实际规则检测，报告绑定精确版本和样例；模板可以被下一阶段调用。原文完整性、错误状态和本地持久化可由自动测试复现。真实公众号接受程度不属于本阶段的已验证结论。
