# 第三阶段验证报告

日期：2026-09-15。范围：模板代码、自动化功能测试、生产构建、生产 HTTP 接口及固定官方检查器进程。未执行公众号实测、系统粘贴、浏览器交互模拟、真实 DeepSeek 请求或真实文章抓取。

## 已实现

- 已保存设计草稿生成声明式模板，保存来源、标签、元素证据、合成节点及语义区域映射。限制标签、样式、嵌套和内容位置，不带入参考作者文字，不执行模型代码。
- 模板渲染标题、正文、引用、列表、强调和分隔线；逐块及逐项核对文字与顺序，拒绝未支持结构。Markdown 解析仍未实现。
- 本地不可变模板版本和检测记录；状态区分草稿、检测中、需修正、通过及失败。记录绑定模板版本、定义哈希、正文哈希和检查器提交；重启后中断的检测不会误判通过。
- 受限本地/AI 行距补丁最多两轮，每轮产生新版本。只允许可定位节点增加 lineHeight；错误、取消及无效报告均不通过。
- 模板列表、详情、来源证据、样例检测/修正、前后样式差异、预览、下载和通过后的复制入口。所有出口使用保存的同一份正文。

实现位于 `src/features/templates/`、`src/app/api/templates/`、`src/app/templates/` 和 `src/components/TemplateWorkspace.tsx`。没有新增依赖。

## 已知限制及后续影响

**行内强调误报。** 实际检查中，字号 16px、行距 1.8 的段落因中间包含 `strong` 收到 line-height 问题。定向检查固定上游 `cli/engine/layout.ts:280–302`，发现其把 `Range.getClientRects()` 的片段数作为行数；同一行中的文本与行内元素可能被计为多行，降低估算行高。上游规范要求检测真实多行重叠，而这种计数不能可靠区分行与片段。

Kanvi 保留原 HTML、样式及规则问题，并添加可能误报的说明。存在行内片段的问题不进入自动行距修正候选，也不会被 AI 补丁绕过。此类模板可能持续处于需修正状态；本阶段未解决上游计数算法，也未证明所有类似诊断都是误报。

**布局重建范围。** 模板语法支持受限自定义嵌套与边框、留白等样式，但自动编译器按正文、标题等角色建立结构，尚未自动重建参考文章复杂区域布局。同角色有多套样式会明确报错。估计值及不支持项仍需查看原分析记录，样例检测不证明视觉还原准确。

**样例覆盖范围。** 样例覆盖长短正文及模板已声明的二级标题、加粗、引用、无序列表和分隔线；不穷举全部标题级别、有序列表、斜体或任意长短组合。下一阶段必须针对每篇新文章重新做内容完整性与规则检查。

模型修正使用受控响应验证，真实 API 的可用性、成本与实际建议质量尚未验证。所有“通过”仅指本次具体样例的规则结果，不是微信平台兼容保证。
