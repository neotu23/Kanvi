日期：2026-09-15。范围：代码、自动功能测试、类型检查、生产构建、生产 HTTP 和固定官方检查器。未执行公众号实测、系统粘贴或浏览器交互模拟；未抓取真实参考文章、未调用真实 DeepSeek。

## 完成能力

单篇 Markdown 在本机解析为带 ID、原文偏移及行列位置的内容块。界面展示诊断，允许手选结构适配且样例规则通过的精确模板版本；本篇独立检测并保存历史，预览、下载和通过后的复制使用同一份正文。

文章历史保存在 `data/articles/<UUID>/article.json`，本篇报告在 `result/report.json`。每次生成独立保存原文、解析结果及版本、模板快照及来源、模板样例报告、本篇正文和指纹。读取时重新解析与渲染以核对绑定；不会拿模板样例报告冒充文章通过。损坏、取消、中断和检查器故障保留失败状态，不覆盖旧结果。

Markdown 通过 mdast/micromark 解析为 AST；GFM 扩展用于识别表格、任务、脚注等结构并明确阻断尚未支持的类型。属性区使用 YAML 1.2 core schema，拒绝别名、锚点、显式标签、重复字段和无效已知字段。精确依赖版本及许可已记录在锁文件与第三方说明中。

## 边界与下一阶段

- 支持文字段落、标题、换行、加粗/斜体、分隔线、单段文字列表与文字段落引用。有序列表保留起始编号。
- 属性区不补写正文；双链保留显示文字且去掉跳转；非折叠提示块转为引用并保留标题/正文。无标题时保留提示类型作为标题，转换有提示。语法符号转换不等于 Markdown 源码逐字输出。
- 媒体、链接、脚注、代码、表格、任务/嵌套/多段列表、嵌套引用、原始 HTML、删除线及部分 Obsidian 扩展明确阻止生成。双链与实体/转义混排无法可靠定位时也会阻断，不猜测替换。
- 结构深度、字符数、文件大小、内容块及诊断数量均有限制。历史按 ID 游标分页，单条损坏记录会使所在页报错；尚未提供备份/恢复或编辑历史。
- 原文完整性测试和实际规则检测分开。已知行内强调误报及复杂参考区域布局未自动还原的限制仍存在。新文章始终单独检测，不自动改模板、不默认换风格。
- 下一阶段实现可选 AI 推荐；目前手选生成无需 Key。规则通过只对应具体输出与固定检查器，不保证微信公众号全部环境兼容。
